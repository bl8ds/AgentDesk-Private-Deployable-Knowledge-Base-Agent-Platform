# MVP 跑通指南：使用方 PDF/图片语料 → 第一场对话

| 项 | 内容 |
|---|---|
| 目标 | 用使用方已给的 PDF/图片，尽快跑通「提问 → 有依据回答」 |
| 原则 | 先通链路，再扩语料；先文本型 PDF，扫描件/图片后置 |
| 关联 | [技术方案正式定稿](./企业级知识库Agent技术方案-正式定稿.md) |

---

## 1. 你要达成的最小结果

能做到下面这件事即算 MVP 跑通：

1. 本地/测试环境服务起来（BFF + Mastra + 模型 Key）。  
2. 使用方若干文档已入库。  
3. 打开对话页，问一句与文档相关的问题，能流式回答并带引用。  

**本阶段不做：** App 换票联调、等级门控、运营后台精美 UI、全量语料、OCR 全覆盖。

---

## 2. 先看清使用方给了什么（你先做的分类）

把文件分成三类，决定能不能直接进 MVP：

| 类型 | 特征 | MVP 怎么处理 |
|------|------|--------------|
| A. 文本型 PDF | 能选中、复制文字 | **优先入库**，本周主攻 |
| B. 扫描件 PDF / 拍照 PDF | 整页是图，选不中字 | 需 OCR；MVP 可先跳过或只挑 1～2 份试 |
| C. 纯图片（jpg/png） | 商品图、海报、截图 | 需 OCR 或先人工整理成说明文字再入库 |

**建议：**  
- 先从使用方包里挑 **5～20 份「能复制文字」的 PDF** 做第一批。  
- 图片和扫描件单独建文件夹 `待OCR`，不挡主链路。

你可自检：用阅读器打开 PDF → 能否拖选文字。能 = A；不能 = B。

---

## 3. 端到端流程（数据怎么进、对话怎么通）

```
① 你整理语料包
      ↓
② 配置模型 Key（Chat + Embedding）
      ↓
③ 启动 Mastra（+ 可选 Go BFF；MVP 可先直连 Mastra 对话）
      ↓
④ 上传/导入文档 → 解析 → 分块 → Embedding → 写入向量库
      ↓
⑤ 对话：提问 → 检索片段 → LLM 生成 → 返回答案+引用
```

| 步骤 | 谁做 | 你具体要干什么 |
|------|------|----------------|
| ① 语料整理 | **你** | 分类、命名、挑第一批、列清单 |
| ② 模型与环境 | **你** | 申请/配置 Key、起服务 |
| ③～④ 入库流水线 | **你配置/触发**；引擎执行 | 调上传或脚本；看任务成功与否 |
| ⑤ 试问验收 | **你** | 按文档出 10 个问题，看能否答上 |

使用方这阶段通常只需：**继续补语料**；不必参与换票（你用测试账号自测即可）。

---

## 4. 推荐落地路径（两档）

### 路径 M1（最快跑通，推荐先做）

只用 **Mastra 自带 RAG**：

1. 起 Mastra + PostgreSQL（或开发用 libSQL）。  
2. 配置国内 Chat / Embedding（OpenAI 兼容 BaseURL）。  
3. 把第一批文本型 PDF 导入 Mastra Knowledge / RAG。  
4. 用 Playground 或临时简易页问一句话。  

**你要写/配的：** 环境变量、导入脚本或管理调用、一个能发消息的最小前端（甚至先用 curl/Playground）。  
**先不必：** Go BFF、一次性码、RAGFlow。

### 路径 M2（文档难、解析差再上）

文本型效果差、或扫描件多时：

1. 部署 RAGFlow（内网）。  
2. 在 RAGFlow 导入 PDF/图片（其 OCR/解析更强）。  
3. 对话仍走 Mastra；检索改调 RAGFlow API，把片段塞进 Prompt。  

**你要做的：** 部署 RAGFlow、配模型、导语料、在 BFF/Mastra 接检索 API。

## 5. 数据录入：你要做的操作清单

### 5.1 语料包规范（建议你建目录）

```
corpus/
  batch-01-text-pdf/     ← 第一批可复制文字的 PDF
  batch-02-scan/         ← 扫描件（后置）
  batch-03-images/       ← 图片（后置）
  manifest.xlsx          ← 文件名、类型、主题、是否已入库
```

`manifest` 建议列：文件名 | 类型(A/B/C) | 主题/业务线 | 入库状态 | 备注。

### 5.2 文本型 PDF 入库（M1）

对每个文件，系统侧自动做（你触发一次即可）：

1. 解析提取文本  
2. 按标题/长度分块（约 200～500 字，可重叠）  
3. Embedding  
4. 写入向量库 + 元数据（文件名、块序号）  

**你负责：**  
- 确认解析后文字是否乱码、是否几乎为空（空 = 其实是扫描件，挪到 batch-02）。  
- 导入失败的文件记到 manifest，单独处理。

### 5.3 图片 / 扫描件（MVP 可选）

| 做法 | 工作量 | 说明 |
|------|--------|------|
| 暂不入库 | 最低 | 先保证 A 类能对话 |
| 人工摘录 | 中 | 把图里关键说明打成 `.md/.txt` 再入库 |
| 接 OCR API | 中高 | 百度/通义等；或放 RAGFlow 处理 |

MVP 建议：**先人工摘 3～5 张关键图的说明文字**，不必一上来接全量 OCR。

---

## 6. 「第一场对话」你怎么验收

准备 10 个问题（必须能在已入库文档里找到答案），例如：

- 「XX 产品保修多久？」  
- 「退货政策是什么？」  

通过标准：

| 项 | 标准 |
|----|------|
| 能回答 | 内容与文档一致，不瞎编关键数字 |
| 有引用 | 能指到文件名/片段 |
| 不会的 | 文档没有时应拒答或说明依据不足 |

不通过 → 先查：是否根本没解析出字、分块是否切碎、Embedding/模型是否配错，而不是先怪 Prompt。

---

## 7. 按天拆：你本周做什么（示例）

| 天 | 你的任务 | 产出 |
|----|----------|------|
| D1 | 分类使用方文件；挑 5～20 份文本 PDF；申请/配置模型 Key | corpus + Key 可用 |
| D2 | 起 Mastra + 存储；打通模型调用（先不管文档，能闲聊也行） | 服务通 |
| D3 | 导入第一批 PDF；抽查解析文本 | 入库成功列表 |
| D4 | 写 10 题试问；调分块/TopK；修坏文件 | 第一场「有引用」对话 |
| D5 | （可选）挂简易 H5 或开始套 Go BFF；扫描件进待办 | 可演示链接 |

App 换票、等级门控：等「对话 + 检索」稳了再接，不挡 MVP。

---

## 8. 职责再明确一次

| 角色 | MVP 阶段做什么 |
|------|----------------|
| **你（平台方）** | 分类语料、起环境、配模型、导入、试问调优、演示 |
| **系统（Mastra/RAGFlow）** | 解析、分块、向量化、检索、生成 |
| **使用方** | 继续提供/确认语料；本期可不参与登录联调 |
| **暂不做** | 全量 OCR、运营后台打磨、生产换票、全量文件一次导完 |

---

## 9. 一句话

**你先挑能复制文字的 PDF → 配好模型和 Mastra → 导入建索引 → 自测 10 个问题跑通带引用的对话。**  
图片和扫描件先放一边或少量人工转文字；解析不够再上 RAGFlow/OCR。
