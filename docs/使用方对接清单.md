## 3. 用户等级门控（配合明细）

> 场景：按使用方用户体系，仅**特定等级**用户开启 AI 功能。

### 3.1 使用方需确认的判定来源（三选一）

| 方式 | 使用方工作 | 特点 |
|------|----------|------|
| A. 令牌内嵌等级（推荐） | 在 code/JWT 中放 `level`/`vip_level`/`role` | 无额外接口，实时性=登录周期 |
| B. 权益查询接口 | 提供 `GET 用户权益(uid)` | 实时性好，需接口联调 |
| C. 权益批量/增量同步 | 推送等级数据到本系统 | 本地判定快，有同步延迟 |

### 3.2 使用方需确认的映射规则（示例，待使用方填写）

| 用户等级 | 是否可用 AI | 日额度 | 可用能力 |
|----------|-------------|--------|----------|
| 普通用户 | 否 / 是 | - | 问答 |
| 会员 | 是 | - | 问答（+商品卡 Phase 2） |
| 高级会员 | 是 | - | 问答 + 高阶（Phase 2） |

### 3.3 交互约定

- 未达标用户：返回 `AI_NOT_ENTITLED`，前端展示升级引导（文案由使用方定）。  
- 等级变更后的生效时效：依所选来源（A/B/C）而定，需使用方确认可接受范围。  
- 越权兜底：前端隐藏入口 + BFF 二次校验。

## 4b. 一次性码换票（正式定义）

**不以「H5 带使用方 Token → 平台方回调使用方验票」为准。**  
正式方案：使用方服务端向平台方领一次性码 → H5 仅用 code 向平台方换 Session。

### 流程

```
使用方 App 客户端 → 使用方 App 服务端 → 平台方 POST /api/v1/auth/app-code → 返回 code
使用方 App 打开 H5?code=xxx
平台方 H5 → 平台方 POST /api/v1/auth/exchange → Session（HttpOnly Cookie）
后续对话仅带平台方 Session
```

### 职责边界

| 事项 | 使用方 | 平台方 |
|------|------|-------------------|
| 实现 `POST /api/v1/auth/app-code`（签发算法、存码、TTL、单次失效） | | ✅ |
| 实现 `POST /api/v1/auth/exchange`（验码、建 Session、映射 AI 权益） | | ✅ |
| Session 校验、对话鉴权、等级门控、额度 | | ✅ |
| App 内判断用户已登录，服务端携带 `sub`、等级等调用 `app-code` | ✅ | |
| 保管「调用平台方 app-code 的服务端凭证」（不下发 App 前端） | ✅ | 平台方颁发该凭证 |
| 将 **仅含 code** 的 URL 交给 WebView 打开 | ✅ | |
| 提供联调用的测试用户 / 联调环境 | ✅ | |
| 实现使用方「验 Token」接口供平台方回调 | ❌ 不需要 | ❌ 不调用 |
| 把使用方业务 Token 传给 H5 / 拼进 URL | ❌ 禁止 | ❌ 不接收 |

### 平台方服务清单（换票相关）

| 服务/模块 | 职责 |
|-----------|------|
| Go Auth | 签发 code、兑换 Session、Session 存储与校验 |
| Go BFF | 对话等业务接口校验 Session；等级门控；额度 |
| H5 | 用 URL 中的 code 调 exchange；之后只带 Session 调 BFF |

### 使用方仅需完成的对接点

1. App 服务端：用户点入口时调平台方 `app-code`（Header 服务端凭证 + Body：`sub`、等级等）。  
2. App 客户端：用返回的 `code` 打开约定 H5 地址。  
3. 字段与等级映射规则书面确认（见 §3）。
