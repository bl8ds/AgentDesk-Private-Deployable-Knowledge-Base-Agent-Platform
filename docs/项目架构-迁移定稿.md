## 1. 实现原则

1. **不做过度拆分**：逻辑上可分模块，**运行时 Go 后端只有一个进程/一个服务**。  
2. **删除独立 Billing 服务**：额度/门控若需要，落在同一 Go 应用的 `modules/` 内，不单独部署。  
3. **Go 必须按 openauth-deploy 规范初始化**：`cmd/`、`modules/`、`internal/`、`api/openapi.yaml`、`migrations/`、`Makefile`、`AGENTS.md`、生产级 `README.md`。  
4. **禁止**：Express/Hono 等自研 TS BFF；未审定前扩栈。  
5. **每个可交付目录必须有生产级 README**（定位、依赖、配置、启动、API、部署），禁止无关话术。  
6. **分支**：`feature/*`，不在 `main`/`master` 直接开发（见 git-workflow）。

## 2. 总共几个应用

### 2.1 自研交付（3 个）

| # | 名称 | 技术 | 职责 |
|---|------|------|------|
| 1 | **agentdesk-api** | Go（openauth-deploy 模板） | 唯一业务后端：OIDC/一次性码会话、知识库上传与任务、对话代理 SSE、用户权益门控、审计 |
| 2 | **agentdesk-chat** | React + Vite（+ assistant-ui） | C 端对话 H5 |
| 3 | **agentdesk-admin** | React + Vite | 运营后台：PDF/文件导入、入库状态、基础配置 |

### 2.2 基础设施 / 现成组件（不自研业务代码）

| 组件 | 方式 | 说明 |
|------|------|------|
| **openauth-auth** | 已有 | `https://auth.example.com` OIDC |
| **PostgreSQL** | 已有 | 库名 `agentdesk`（含 `vector` 扩展，开发机已建） |
| **Redis** | 已有 | 会话/限流可选 |
| **agentdesk-agent** | **Docker 部署 + 配置**（`apps/agentdesk-agent/`），不二次开发框架 | Agent/RAG 运行时（Mastra）；agentdesk-api 调其 HTTP API |
| MinIO | 可选复用 | 原文件存储；MVP 可用本地卷 |

**合计：自研 3 个应用 + agentdesk-agent 容器（配置部署）+ 复用 Auth/PG/Redis。**

## 3. agentdesk-agent：开发还是 Docker？

| 决策 | 说明 |
|------|------|
| **默认：Docker 部署** | 应用源码在 `apps/agentdesk-agent/`；Compose 构建为 `agentdesk-agent` 服务 |
| **不开发** | 不在仓库内用 Express 重写 Agent；不做 Mastra 框架级二开 |
| **允许的配置工作** | 模型 BaseURL、Embedding、系统提示、与 agentdesk-api 的内网 URL |
| **agentdesk-api 职责** | 鉴权通过后转发对话/入库请求到 agentdesk-agent（`AGENT_BASE_URL`）；不把框架源码嵌进 Go 仓库 |

解析能力不足（扫描件/复杂 PDF）时：**另议 RAGFlow 容器**，仍不自研解析引擎。

## 4. 运行时架构（实现形态）

```
agentdesk-chat / agentdesk-admin
        │
        ▼
   agentdesk-api  ←── 唯一 Go 服务（openauth-deploy 规范）
        │
        ├── openauth-auth（OIDC / JWKS）
        ├── PostgreSQL (agentdesk)
        ├── Redis（可选）
        └── agentdesk-agent（Docker，内网）
                 └── LLM / Embedding（OpenAI 兼容）
```

逻辑分层（均在 **agentdesk-api** 内，非独立进程）：

| modules 建议 | 职责 |
|--------------|------|
| `authz` / `session` | OIDC 回调或 JWKS、一次性码换票、Session |
| `entitlement` | 用户等级门控（原 Billing 能力收敛于此，无独立服务） |
| `knowledge` | 上传、触发 Agent 入库、文档状态 |
| `chat` | SSE 代理 agentdesk-agent 对话 |
| `audit` | 操作/提问审计 |
| `health` | 健康检查 |
| `agent` | HTTP client（`AGENT_BASE_URL`） |

## 5. Go 工程规范（强制对齐 openauth-deploy）

初始化时复制/对照模板，并遵守其 `AGENTS.md`：

| 项 | 要求 |
|----|------|
| 语言 | Go only（本服务） |
| 布局 | `cmd/app`、`cmd/migrate`、`modules/*`、`internal/`、`api/openapi.yaml`、`migrations/` |
| 领域包 | 扁平：`store.go` / `svc.go` / `handler.go` / `router.go` |
| 命名 | `*Store`，禁止 `*Repository` |
| DB | **无物理外键**；逻辑 `*_id`；应用层约束 |
| API | `/api/v1/`；OpenAPI；成功 envelope；错误 RFC 7807 Problem Details |
| 鉴权 | 生产 JWKS（openauth-auth）；本地可 `AUTH_MODE=local` |
| 文档 | 根目录生产级 `README.md` + `AGENTS.md` |

参考路径：`reference-go-template`。

## 9. 语料导入路径

1. 运营打开 **agentdesk-admin** → 知识库上传。  
2. **agentdesk-api** 收文件、落存储、调 agentdesk-agent 入库 API。  
3. 状态在 agentdesk-admin 展示（pending / ready / failed）。  
4. agentdesk-chat 提问 → agentdesk-api → agentdesk-agent 检索生成 → SSE。

文本型 PDF 优先；图片/扫描件需 OCR 或后置，见《MVP跑通指南》。
